# Развёртывание и замена действующего сайта

## Vercel с существующим обработчиком

Импортировать `IMONsergey/debtupd` как **отдельный проект**, не менять старый проект. Команда сборки `npm run build`, выходная папка `dist`, Node.js 22. Файл `vercel.json` проксирует `/api/lead` к `https://debt-2026-lite.176.98.177.253.sslip.io/api/lead` — тому же стабильному backend, который использовал старый сайт. Такой адрес не создаёт цикл после переноса `debt-tech.ru`.

Получить preview URL, открыть его на телефоне и компьютере, проверить меню, видео и фотографии. До подключения домена основной сайт и его заявки продолжают работать отдельно.

На тестовом домене Метрика намеренно выключена. На основном домене счётчик 104151247 включится автоматически. Kinescope загружается только после открытия видео.

## Собственный сервер

```sh
cp .env.example .env
# Перенести реальные значения из secret store старого сервера в .env.
# Затем:
docker compose up -d --build
```

Существующий HTTPS reverse proxy должен направлять тестовый домен на `http://127.0.0.1:8080`. Сервис `forms` доступен только внутри сети Compose. Если используются уже работающие Bitrix24 / Telegram, сохраняются category 15, стадии C15:NEW / C15:PREPARATION и UF_CRM_DEBT2026_* поля. Секреты не включаются в клиентскую сборку и не хранятся в Git.

Обработчик не возвращает успех без подтверждённой доставки хотя бы в Bitrix24 или Telegram. При отсутствии конфигурации отвечает 503. Если используется Bitrix24, его подтверждение является основным; Telegram — дополнительное уведомление.

## Проверка перед переключением

1. Убедиться, что актуальные цена, дата и состав тарифов согласованы. Указанные в этой версии цены действуют до 1 октября; после этой даты их необходимо обновить.
2. На preview проверить три вида формы. Сначала ошибки без отправки, затем одну согласованную реальную заявку с понятной пометкой — подтверждение в интерфейсе, сделку и реквизиты в Bitrix24, уведомление Telegram.
3. Убедиться, что `/api/lead` не отдаёт HTML приложения и недоступность backend показывает ошибку пользователю.
4. Проверить 320, 390, 768, 1181, 1440 и широкий экран; видео, телефон, почту, карту, галерею, приватность.
5. Сохранить прежний deployment и конфигурацию домена. Подключить основной домен только после приёмки preview и серверного сценария.
6. После переключения проверить HTTPS, Метрику в реальном времени и ещё одну согласованную заявку. При проблеме вернуть домен на прежний deployment.

В этой сессии production-домен не переключался, реальные заявки не создавались и серверные секреты не копировались. Автоматические проверки доказывают корректность клиентских сценариев и обработки ответов, но не факт доставки в живую CRM.
