Локальный Vite и GitHub Pages по умолчанию не отправляют Метрику. Kinescope, карты, программа, контакты и ссылки сохранены из действующего сайта. Песочница закрыта от индексации заголовком `X-Robots-Tag` и `robots.txt`; это не парольная защита.

## Сборка и публикация только песочницы

Требуется Node.js 22+. Сначала проверить `git status`, не включать посторонние изменения.

```sh
npm ci
npm test
npm run test:e2e
VITE_METRIKA_HOSTS=debtupd-sandbox.176.98.177.253.sslip.io npm run build
```

Архив содержит только `dist`, `server`, `deploy`, `package.json`. Никаких `.env`, SSH-ключей, webhook URL или токенов.

```sh
release="$(date -u +%Y%m%dT%H%M%SZ)-$(git rev-parse --short HEAD)"
mkdir -p test-results/deploy
COPYFILE_DISABLE=1 tar --no-xattrs -czf "test-results/deploy/$release.tgz" dist server deploy package.json
ssh debt-2026-lite "mkdir -p /srv/imon/projects/debtupd-sandbox/releases/$release"
scp "test-results/deploy/$release.tgz" "debt-2026-lite:/srv/imon/projects/debtupd-sandbox/releases/$release/release.tgz"
ssh debt-2026-lite "cd /srv/imon/projects/debtupd-sandbox/releases/$release && tar -xzf release.tgz && bash deploy/install-sandbox.sh $release"
```

Установщик копирует секреты существующего сервиса **внутри сервера**, создаёт отдельный env с правами `600`, меняет только порт и origin. Повторный запуск сохраняет секреты песочницы. Env читает systemd; значения не оказываются в сборке, Git или логах. Node 22 использует уже установленный runtime старого проекта (read-only).

Caddy получает отдельный `import /etc/caddy/debtupd-sandbox.caddy`; прежние host blocks не меняются. Перед graceful reload сохраняется backup и выполняется `caddy validate`. `current` и `source` песочницы указывают на release; предыдущие пути печатаются для отката **только песочницы**.

После выкладки проверить HTTPS, JS/CSS, все три формы, реальную сделку и товары в Битрикс, Telegram, Метрику, видео и карту. В журнал пишутся только тип формы и ID подтверждённой сделки/сообщения, без персональных данных и секретов:

```sh
ssh debt-2026-lite 'journalctl -u debtupd-sandbox-forms.service --since "10 minutes ago" --no-pager'
```

Подтверждение `success: true` опирается на Битрикс, Telegram отправляется следом. Ошибка Telegram не отменяет уже созданную сделку; проверить `telegram_delivered` либо `telegram_async_delivery_failed`. Не повторять запрос вслепую при таймауте: сначала проверить доставку, иначе возможны дубли, как в исходном обработчике.

## Локальная проверка

`npm run dev` проксирует формы только на локальный `127.0.0.1:32027`, а не на действующий домен. В другом терминале можно запустить `PORT=32027 npm run forms:telegram`; без секретов корректная заявка получит 503, а не ложный успех. Для локальной проверки UI автотесты подменяют ответы API. Серверные тесты используют изолированный transport fixture без внешних запросов.

`vercel.json`, Docker Compose и GitHub Pages остаются альтернативными конфигурациями исходного проекта и не участвуют в этой выкладке. Не запускать их как способ обновления текущей песочницы.
